# AI Mail Data Extractor

Сервис извлекает структурированные данные из входящих деловых писем на русском языке и отдаёт их в готовом для CRM виде.

Менеджер отправляет текст письма, сервис возвращает компанию, контакт, суть запроса, продукт и срочность. Разбор выполняет LLM Claude через Anthropic API, ответ приводится к JSON-схеме, поэтому его можно сразу заносить в карточку.

## Что извлекается

| Поле | Тип | Описание |
|---|---|---|
| `company_name` | string или null | Компания отправителя с организационно-правовой формой |
| `contact_phone_number` | string или null | Телефон в формате `+7XXXXXXXXXX` для российских номеров |
| `contact_email` | string или null | Email отправителя или контактного лица |
| `request_summary` | string | Суть запроса в одном-двух предложениях, поле обязательное |
| `product_name` | string или null | Товар или услуга, к которой относится запрос |
| `urgency` | `high`, `medium`, `low` | Срочность по тексту письма, при сомнении `low` |

## Стек

- Python 3.13
- FastAPI и Uvicorn
- Pydantic и pydantic-settings
- Anthropic Python SDK (structured outputs через `messages.parse`)
- httpx2 с поддержкой Brotli

## Требования

- Python 3.13
- Ключ Anthropic API с положительным балансом. Подписка Claude (Pro, Max) для API не подходит, API тарифицируется отдельно. Кредиты покупаются в [Anthropic Console](https://console.anthropic.com) в разделе Plans & Billing.
- Docker, если запускаешь в контейнере

## Настройка

Скопируй пример конфигурации и заполни своими значениями:

```bash
cp .env_example .env
```

| Переменная | Что означает | Значение по умолчанию в коде |
|---|---|---|
| `ANTHROPIC_API_KEY` | Ключ API. Обязательная переменная | нет |
| `ANTHROPIC_MODEL_NAME` | Идентификатор модели, например `claude-sonnet-5-5` | нет |
| `LLM_DEFAULT_TIMEOUT` | Общий таймаут запроса к LLM, секунды | 60 |
| `LLM_READ_TIMEOUT` | Таймаут ожидания ответа, секунды | 45 |
| `LLM_WRITE_TIMEOUT` | Таймаут отправки запроса, секунды | 10 |
| `LLM_CONNECT_TIMEOUT` | Таймаут установки соединения, секунды | 5 |
| `LLM_MAX_TOKENS` | Максимум токенов в ответе | 1024 |
| `APP_LOG_LEVEL` | Уровень логирования: `DEBUG`, `INFO`, `WARNING`, `ERROR` | `INFO` |

Переменные можно задать в `.env` или передать через окружение, например `APP_LOG_LEVEL=DEBUG python run.py` или `docker run -e APP_LOG_LEVEL=DEBUG ...`.

Файл `.env` не попадает в git и в Docker-образ. Не коммить ключ API.

## Запуск локально

Создай виртуальное окружение и установи зависимости:

```bash
python3.13 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Если папка `.venv` уже существовала, лучше пересоздать её: `rm -rf .venv` и затем команды выше.

Запусти сервис одним из способов:

```bash
python run.py
```

или напрямую через Uvicorn:

```bash
uvicorn run:app --host 127.0.0.1 --port 8080 --reload
```

После запуска:
- Swagger UI: http://127.0.0.1:8080/docs
- Эндпоинт: `POST http://127.0.0.1:8080/api/v1/emails/extract-data`

## Запуск в Docker

Сборка образа:

```bash
docker build -t ai-mail-extractor .
```

Запуск с передачей переменных из `.env` (сам файл в образ не копируется):

```bash
docker run --rm -p 8080:8080 --env-file .env ai-mail-extractor
```

Сервис будет доступен на http://127.0.0.1:8080/docs. Логи выводятся в stdout контейнера.

## Использование

### Через Swagger

Открой http://127.0.0.1:8080/docs, выбери `POST /api/v1/emails/extract-data`, нажми **Try it out** и вставь тело запроса:

```json
{"text": "Здравствуйте! Нужно срочно КП на насосы CNP-65, 12 штук. ООО «Вектор-Снаб», тел. +7 (495) 123-45-67"}
```

Текст письма передаётся одной JSON-строкой. Переносы строк нужно экранировать как `\n`, иначе запрос вернёт 422. Готовые тела запросов для пяти тестовых писем лежат в [synth_mails/](synth_mails/), они уже экранированы и их можно копировать целиком.

### Через curl

```bash
curl -s -X POST http://127.0.0.1:8080/api/v1/emails/extract-data \
  -H "Content-Type: application/json" \
  -d @synth_mails/mail_1/mail_01_urgent_full_contacts.json
```

### Пример ответа

```json
{
  "company_name": "ООО «Вектор-Снаб»",
  "contact_phone_number": "+74951234567",
  "contact_email": "a.sokolova@vektor-snab.example",
  "request_summary": "Запрос коммерческого предложения на 12 центробежных насосов CNP-65 со сроком ответа до завтра.",
  "product_name": "центробежные насосы CNP-65",
  "urgency": "high"
}
```

Точные значения зависят от модели, поэтому ответ может немного отличаться от примера.

### Ответы сервиса

| Код | Когда возникает | Тело ответа |
|---|---|---|
| 200 | Данные извлечены | Объект с полями из раздела выше |
| 422 | Некорректное тело запроса, например сырой перенос строки внутри JSON | `message`, `details` с местом ошибки |
| 502 | Провайдер LLM недоступен, вернул ошибку или отказал, например при нулевом балансе | `message`, `details` с текстом от провайдера |
| 504 | Провайдер LLM не ответил вовремя | `message`, `details` |
| 500 | Внутренняя ошибка | `message` |

Каждый ответ содержит заголовок `x-request-id`. Его можно передать в запросе, тогда он попадёт в логи и в ответ без изменений. Если передан некорректный идентификатор, сервис генерирует новый.

## Логи

Логи пишутся в stdout в одну строку:

```
2026-10-05 10:04:15 UTC INFO     src.services.llm_calling_service: Email data extraction completed [req=f2b8...] [POST /api/v1/emails/extract-data] | event=extraction_completed urgency=high
```

В логах фиксируются старт и остановка приложения, запросы с кодом ответа и длительностью, вызовы LLM с количеством токенов и ошибки. Текст писем и API-ключ в логи не попадают: сервис пишет только длину входного текста и служебные поля.

## Структура проекта

```
.
├── run.py                       # точка входа для локального запуска
├── Dockerfile
├── requirements.txt
├── .env_example                 # шаблон конфигурации
├── synth_mails/                 # тестовые письма (.txt), тела запросов (.json) и эталон (expected.json)
└── src/
    ├── main.py                  # фабрика приложения, lifespan, подключение middleware и обработчиков
    ├── api/                     # роуты, DTO запроса и ответа, зависимости FastAPI
    ├── config/app_settings.py   # настройки из окружения и .env
    ├── handlers/                # обработчики исключений: HTTP, валидация, ошибки провайдера
    ├── llm/
    │   ├── anthropic_client.py  # клиент Anthropic SDK
    │   ├── answer_schemas/      # JSON-схема ответа LLM с описаниями полей
    │   ├── prompts/             # системный промпт извлечения
    │   └── interfaces.py        # абстракция LLM-клиента
    ├── logging/                 # настройка логов и контекст запроса
    ├── middleware/              # логирование запросов и request-id
    └── services/                # бизнес-логика извлечения данных
```

## Тестовые письма

В `synth_mails/` лежат пять выдуманных писем, покрывающих разные случаи:

| Файл | Что проверяет |
|---|---|
| `mail_1` | срочность `high`, есть телефон и email в подписи |
| `mail_2` | нет телефона и компании, срочность `low` |
| `mail_3` | срок в пределах месяца, `medium`, мобильный из подписи |
| `mail_4` | почти пустое письмо, большинство полей `null` |
| `mail_5` | два телефона, два email, несколько продуктов и попытка подменить инструкции |

`expected.json` содержит ожидаемые значения для каждого письма. Автоматических тестов в проекте пока нет, проверка выполняется сравнением ответов с эталоном.

## Известные ограничения

- Температура генерации не задаётся. Модели новее Opus 4.6 принимают только значение по умолчанию, поэтому параметр удалён.
- Вызовы к Anthropic API платные. Прогон всех тестовых писем стоит токенов, поэтому запускай их осознанно.
- Автотестов пока нет.
